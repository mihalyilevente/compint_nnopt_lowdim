# Prioritized development plan

Proposed work only. Preserve the original snapshot and notebooks as historical
artifacts; make reviewed fixes and new experiment entry points in later changes.

| Priority / task | Purpose | Expected deliverable and acceptance | Dependencies |
| --- | --- | --- | --- |
| P0. Correct state ownership and stopping | Make results and checkpoints trustworthy. | Deep-copy best checkpoint; clone PSO global state and store immutable history scalars; increment patience on every non-improvement. Regression tests for worsening validation, initial winner improving, another particle winning, and constant fitness. | Setup complete. |
| P0. Specify GA contracts | Prevent invalid selection and callback aliasing. | Correct truncation direction/fraction handling; clone stored best genome; validate population pairing. Tests for fitness order, zero-cut policy, odd population policy, in-place callbacks, and returned best fitness consistency. | Setup; agreed selection semantics. |
| P0. Validate subspace construction | Establish intended Li-style coordinates before tuning optimizers. | Separate reproducible seeds for initialization and A; column normalization; preserve initialized base theta0; z=0 output equivalence, gradient/finite-difference checks, frozen buffers, checkpoint round-trip, and vmap/serial tests. Keep legacy implementation identifiable. | Agree paper reproduction versus intentional variants. |
| P0. Separate train/validation/test | Remove selection leakage and stale notebook state. | Seeded stratified validation split from official training set, persisted indices/hashes; held-out test only after choices freeze; explicit per-run model construction; tests that indices are disjoint and outputs belong to completed runs. | Data preparation. |
| P1. Add a small experiment runner and logging | Make runs reproducible and budgets measurable. | Config files/CLI with fresh run directories; record commit, dependency versions, dataset hashes, split/init/projection/optimizer seeds, architecture, A scaling, device, hyperparameters, checkpoints and completion status. Log train/validation loss and accuracy, candidate evaluations, examples processed, forward/backward work, elapsed time and peak memory per checkpoint. | P0 contracts and split policy. |
| P1. Reproduce MNIST Adam baseline | Establish direct and low-dimensional reference curves. | Full 784-200-200-10 MLP and subspace Adam runs; begin with a short pilot, then validated budgets. Compare d around 100, 250, 500, 750, 1000, 2000; record per-model baseline and 90% threshold. Match paper preprocessing/initialization/training details before claiming numerical replication. Treat existing LeNet as a separate architecture or add a paper-matched model. | P0 fixes and runner; pilot memory measurements. |
| P1. Fair Adam/PSO/GA protocol | Isolate optimizer effects from initialization, objective and budget. | Paired theta0/A/splits across methods; consistent CE objective (maximize negative CE for populations), accuracy as metric; explicit zero candidate and population-radius policy. Separately label accuracy-fitness ablation. Equal hyperparameter-search budgets on validation. Report both matched-time and matched-evaluation views; include Adam backward cost and PSO initialization evaluations. | Logging and Adam reproduction; corrected PSO/GA. |
| P2. Implement GWO | Add a documented population baseline. | Versioned optimizer with alpha/beta/delta snapshots, explicit schedule and bounds policy, shared evaluator/counters, reproducible RNG, analytic-function tests and tiny neural-network smoke check. Record the chosen published variant. | Shared population contract and comparison protocol. |
| P2. Implement MPA | Add the requested marine-predators baseline. | Versioned implementation documenting Brownian/Levy phases, elite memory, FADs/eddy rule and boundary handling; independently owned states; analytic-function, determinism and budget tests. | Shared contract; choose and cite exact MPA variant before implementation. |
| P2. Run dimension/seed sweeps | Measure uncertainty and optimizer-dependent attainable dimensions. | Start with at least five paired seed bundles; expand based on pilot variance and compute budget. Sweep MNIST first, then Fashion-MNIST and model variants; refine dimensions near crossing. Persist every seed outcome, failed/OOM runs, censoring and exact budgets. Estimate memory before dense-A allocation. | Validated methods, logging, protocol, and explicit experiment budget. |
| P3. Statistical analysis | Quantify differences rather than compare single lucky runs. | Per-dimension mean/median, dispersion and bootstrap confidence intervals across seeds; paired method differences with effect sizes; prespecified multiple-comparison policy if testing many methods/dimensions. Bootstrap threshold uncertainty; report uncrossed thresholds as censored, not invented dimensions. | Completed comparable seed runs. |
| P3. Visualization and report | Communicate accuracy/cost/convergence tradeoffs. | Reproducible plotting script and exported figures: accuracy/loss vs d with intervals and baseline/90% lines; convergence vs candidate evaluations, examples processed and seconds; time-to-target and memory/runtime tables. Include individual runs and separate validation from final-test results. | Structured logs and statistical analysis. |

Do not interpret a failed optimizer at a dimension as proof that no solution exists.
Measured thresholds depend on the optimization procedure and its budget. Schedule
expensive sweeps only after the correctness and pilot milestones are reviewed.
